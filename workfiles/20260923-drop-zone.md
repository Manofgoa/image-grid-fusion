# Drop Zone

> Working document — a dedicated drop zone to the right of the preview, to add images without
> replacing the ones already placed.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

Today, files dropped **onto a cell** of the preview replace that cell (intended, kept as is).
Files dropped elsewhere in the window are added like a paste — but once the preview fills most
of the window, "elsewhere" is a thin margin that is hard to hit. The user has no obvious target
to simply **add** images.

Goal: a permanent **drop zone** to the right of the preview canvas, whose only job is to add
images after the existing ones. It also opens a file picker when clicked.

Relevant components:

| File | Role |
|---|---|
| `UI/GridPreview.cs` | Paints the canvas (`CanvasBounds`, centered, 16 px margin, 1200 × 628 ratio), hit-tests cells (`CellAt`), highlights the external drop target (`ShowDropTarget`), `Add(images, targetCell)` |
| `UI/MainForm.cs` | Wires drag & drop (`OnDragEnter`, `OnPreviewDragOver`, `OnDragDrop`), `AddFilesAsync(paths, targetCell)` loads off the UI thread and reports skipped / ignored files in the status line |

---

## Current Behaviour (as found in the code)

- `OnDragDrop`: dropped on `_preview` → `DropCell(e)` (cell index or -1); dropped on the form → -1.
  `AddFilesAsync(paths, target)` then calls `_preview.Add(images, target)`.
- `Add` with `targetCell = -1`: images fill the free slots; the **first excess** image replaces
  the selected cell (else the last one); further excess is disposed and reported as ignored.
- Empty state: the whole canvas is a dashed rectangle reading
  *"Drop 1 to 4 images here, or paste them with Ctrl+V"*.
- `ImageLoader.TryLoadFile` has no extension filter: it tries to decode any file and reports
  failures as "skipped".

## Drop Zone — Behaviour

Agreed with the user (scoping batch):

- **Drop = append** after the images already loaded, never replacing a cell by target. Same path
  as a paste: `AddFilesAsync(paths)` with no target cell.
- **Always visible**, to the right of the preview canvas, and **highlighted while files are
  dragged over it** (same highlight colour as a targeted cell).
- **Click = file picker** (multi-select); the chosen files are added exactly like a drop.

- **Grid full (4 images)**: the zone stays **active** and applies the existing excess rule — the
  first extra image replaces the selected cell, else the last one; further extras are ignored
  and reported in the status line.
- **Empty state (0 image)**: the zone is **shown anyway**, so the layout does not jump when the
  first image arrives. The canvas keeps its own empty-state drop target.
- **File picker**: multi-select. Filters, the first being the default: "Supported files" (all of
  the following), "Images" (png, jpg, jpeg, bmp, gif, tif, tiff, webp), "Videos" (the extensions
  `VideoFrames` accepts), "PDF", "Text" (txt, md, log, csv, json, xml — text is detected by
  content, so these are only the common ones), then "All files".

## Drop Zone — Look and Placement

- A vertical strip, the **height of the canvas**, on its right, separated from it by the canvas
  margin. The canvas shrinks horizontally to make room (it keeps its ratio and stays centered in
  the remaining area).
- Dashed border (same style as the empty state), a **"+"** (2/5 of the zone width, 32 px at
  most) above the label *"Add images"*, the pair vertically centered. Mouse hover: border, "+"
  and label turn white, hand cursor.
- During a file drag over it: filled with the cell highlight colour and outlined like a hovered
  cell.
- Width: 96 logical pixels (DPI-scaled); the gap to the canvas is the canvas margin (16).
- The **right side is reserved** for the zone. `20260923-layout-variants.md` puts its layout
  thumbnail strip on the **left** of the preview, so both coexist: thumbnails | canvas | drop zone.

## Code Impact

- `GridPreview` paints and hit-tests the zone itself (one control, one coordinate space):
  `DropZoneBounds(canvas)` next to `CanvasBounds()`, which reserves its width and gap on the
  right; `ShowDropTarget(Point?)` (`DropTargetBounds`, `SurfaceAt`) returns the zone when the
  point is on it; `PaintDropZone`; a `DropZoneClicked` event raised on a press **and** release
  on the zone. Pressing the zone keeps the selection, so a full grid still replaces the
  selected cell.
- `MainForm`: drops need no change — `DropCell` is -1 on the zone, so the files are appended.
  `DropZoneClicked` → `PickFiles()`: `OpenFileDialog` titled "Add images", `Multiselect`,
  the filters of the File picker rule above, then `AddFilesAsync(dialog.FileNames)`.

## Design Iterations

Chronological log of design refinements, of the choices the implementation run
took on its own — flagged `🧭 Implementation choices` — and of every adjustment
requested afterwards — flagged `⚙️ Post-implementation`. One entry per request,
in the order the requests were made.

### Iteration 1 — 2026-09-23

Initial design. Scoping batch settled the core behaviour: drop appends, zone always visible and
highlighted during a drag, click opens a file picker, subject expected to be straightforward
(single exploration pass, done directly). Proposal: a vertical strip right of the canvas,
painted and hit-tested by `GridPreview`, wired in `MainForm`. Seven open questions listed.

### Iteration 2 — 2026-09-23

User answers (Q&A #5–8): the zone stays active on a full grid with the existing excess rule; it
is shown in the empty state too; look and implementation proposals accepted (vertical strip the
canvas height, painted and hit-tested inside `GridPreview`). Behaviour, look and code impact
sections updated accordingly.

### Iteration 3 — 2026-09-23

User answers (Q&A #9–11): the file picker defaults to image extensions with "All files" as
second choice; no unit tests; the right side is reserved for the drop zone and the note is added
to `20260923-layout-variants.md`, which meanwhile settled its thumbnail strip on the **left** —
no conflict. No open question remains.

### Iteration 4 — 2026-09-24 — ✅ Implemented

Go given (Q&A #12–13): code, tests and documentation — tests being declined, that means code and
README. Work stays on `main` by the user's choice. Scope frozen on the sections above.

### Iteration 5 — 2026-09-24 — 🧭 Implementation choices

- **Code had moved since the design**: the layout strip (left), the drag ghost and the hover
  outline were already in. The zone plugs into them: `ShowDropTarget` now takes a point, so
  the zone is resolved inside `GridPreview` and the planned public `IsOverDropZone` was not
  needed; during a file drag the zone gets the same fill and outline as a cell.
- **No `MainForm` change for drops**: `DropCell` already returns -1 on the zone, which appends.
- **Click** fires on press and release both on the zone (button semantics), and keeps the
  selection.
- **Hover look**: border, "+" and label turn white (the normal colour is already light grey).
- **"+" size**: 2/5 of the zone width, 32 px at most; label below, pair vertically centered.
- **Picker**: titled "Add images", filter labelled "Images", no initial folder (Windows
  reopens the last one used).
- No project rule broken. Work done on `main` (user's choice).
- **Noticed, not done**: another session has uncommitted work adding non-image sources
  (PDF, video, text pages) to `ImageLoader`. If it lands, the picker's "Images" filter will not
  list those extensions — added as an Open Question.

### Iteration 6 — 2026-09-24 — ⚙️ Post-implementation — Picker lists every supported file type

User request (Q&A #14): the picker also lists the PDF, video and text files the app now reads.
A "Supported files" filter comes first and groups everything; per-type filters follow, then
"All files". Video extensions mirror `VideoFrames`; text being detected by content, the "Text"
filter lists the common extensions only. No test, at the user's request. Task closed after this
adjustment.
