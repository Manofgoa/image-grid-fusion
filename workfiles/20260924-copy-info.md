## Overview

Today `Copy` reports `Copied to the clipboard (W × H).` and `Save…` reports
`Saved {name} (W × H).`, both cleared after 4 s. The goal: a richer summary of what was
actually produced — file name, format, dimensions, file size, frame count, duration, encoding
time — that stays visible until another status message replaces it.

Relevant components:

| Component | Role |
|---|---|
| `UI/MainForm.cs` | `CopyToClipboard()`, `Save()`, `ShowStatus()` with its 4 s / 8 s `_statusTimer` |
| `Imaging/GridExport.cs` | MP4 export (`RenderVideo`, 30 fps, `Result(Size, SoundProblem)`) and still export (`RenderStill`) |
| `Composition/Animation.cs` | `FrameCount(length)`, `FrameTime(k)` — frame count and timing of the video |

**Dependency**: the MP4 export of `Copy` / `Save…` belongs to
[animated-content](20260924-animated-content.md), **being implemented in another session**:
`GridExport.cs` / `VideoEncoder.cs` are committed (`bd9e4f7`), but `MainForm` does not call them
yet. This workfile builds on that wiring and is implemented **after** that run has landed on
`main`.

## Summary Content

One line, fields separated by ` · ` like the other multi-part status messages.

| Field | Still (PNG) | Video (MP4) | Source of the value |
|---|---|---|---|
| Verb + name | `Copied to the clipboard` / `Saved {name}` | `Copied {name}` (temp file under `%TEMP%\ImageGridFusion\`) / `Saved {name}` | dialog file name, temp file name |
| Format | `PNG` | `MP4 video` | export branch taken |
| Dimensions | `1920 × 1080` | `1920 × 1080` (even-rounded canvas) | rendered bitmap / `Result.Size` |
| File size | PNG stream size (copy) or file size (save) | size of the written `.mp4` | `MemoryStream.Length` / `FileInfo.Length` |
| Frames | `1 frame` | `300 frames` | `1` / `Animation.FrameCount(job.Length)` |
| Duration | `0 s` | `10.0 s` | `0` / `job.Length` |
| Sound | — (not shown) | `sound: clip.mp4` / `no sound` | `job.SoundPath` file name, `no sound` when none was written |
| Encoding time | `encoded in 0.3 s` | `encoded in 3.2 s` | `Stopwatch` around render + encode |

- Frames and duration are **always shown**, even for a still (`1 frame · 0 s`), so the format
  of the line stays constant. The sound field exists only for a video — a PNG never has one.
- No frame rate: the video is always 30 fps, frames + duration already say it.
- File size in binary units, one decimal: `845 KB`, `12.4 MB` (bytes below 1 KB).
- Duration and encoding time: one decimal, `s` suffix.
- Examples:
  - `Copied to the clipboard · PNG · 1920 × 1080 · 2.1 MB · 1 frame · 0 s · encoded in 0.3 s`
  - `Saved fusion-20260924-101500.mp4 · MP4 video · 1920 × 1080 · 12.4 MB · 300 frames · 10.0 s · sound: clip.mp4 · encoded in 3.2 s`
- A sound problem reported by the export (`Result.SoundProblem`) keeps being reported as the
  animated-content run does it; the sound field then reads `no sound`.

## Status Line Lifetime

- **Every** status message — the copy / save summary, paste, removal, skipped files, errors —
  stays **until the next status message** replaces it.
- `_statusTimer` and its 4 s / 8 s intervals are **removed**; errors keep their red colour.

---

## Status Line Layout

- A message wider than its column **wraps** onto further lines instead of being cut: the status
  label keeps the middle (`Percent 100`) column of the bottom `TableLayoutPanel` and wraps within
  its width; the bottom bar, `AutoSize`, grows in height, the preview above shrinks accordingly.
- It re-wraps when the window is resized.

## Design Iterations

Chronological log of design refinements, of the choices the implementation run
took on its own — flagged `🧭 Implementation choices` — and of every adjustment
requested afterwards — flagged `⚙️ Post-implementation`. One entry per request,
in the order the requests were made.

### Iteration 1 — 2026-09-24

Initial design from the request and the scoping batch: the summary carries file name, format,
dimensions, file size, frame count, duration and encoding time; frames and duration are shown
for a still too; the summary persists until the next status message. Built on the MP4 export
of the animated-content workfile, implemented after it lands. Four questions remain open.

### Iteration 2 — 2026-09-24

Open questions answered: every status message now persists until the next one (the timer goes
away, not only for the summary); a video's summary names its sound source (`sound: clip.mp4` /
`no sound`); no frame rate; a message wider than the window wraps and the bottom bar grows.
The MP4 export it builds on has since been committed on `main` (`bd9e4f7`). No question remains.

### Iteration 3 — 2026-09-24 — ✅ Implemented

Go given for the code only (unit tests: no test project; README: not authorised). Work lands on
`main`, the app's standing rule. The run waits for the animated-content session to commit its
in-progress `MainForm.cs` / `GridExport.cs` edits before touching them.
