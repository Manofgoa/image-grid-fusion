# Copy Info

> Working document — after `Copy` or `Save…`, the status line describes what was produced.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

Today `Copy` reports `Copied to the clipboard (W × H).` and `Save…` reports
`Saved {name} (W × H).`, both cleared after 4 s. The goal: a richer summary of what was
actually produced — file name, format, dimensions, file size, frame count, duration, encoding
time — that stays visible until another status message replaces it.

Relevant components:

| Component | Role |
|---|---|
| `UI/MainForm.cs` | `CopyToClipboard()`, `Save()`, `ShowStatus()` with its 4 s / 8 s `_statusTimer` |
| `Imaging/GridExport.cs` | MP4 export (`RenderVideo`, 30 fps, `Result(Size, Length, Frames, SoundPath, SoundProblem)`) and still export (`RenderStill`) |
| `Composition/Animation.cs` | `FrameCount(length)`, `FrameTime(k)` — frame count and timing of the video |

**Dependency**: the MP4 export of `Copy` / `Save…` belongs to
[animated-content](20260924-animated-content.md); this workfile was implemented on top of its
`MainForm` wiring once that had landed on `main`.

## Summary Content

One line, fields separated by ` · ` like the other multi-part status messages.

| Field | Still (PNG) | Video (MP4) | Source of the value |
|---|---|---|---|
| Verb + name | `Copied to the clipboard` / `Saved {name}` | `Copied {name}` (temp file under `%TEMP%\ImageGridFusion\`) / `Saved {name}` | dialog file name, temp file name |
| Format | `PNG` | `MP4 video` | export branch taken |
| Dimensions | `1920 × 1080` | `1920 × 1080` (even-rounded canvas) | rendered bitmap / `Result.Size` |
| File size | PNG stream size (copy) or file size (save) | size of the written `.mp4` | `MemoryStream.Length` / `FileInfo.Length` |
| Frames | `1 frame` | `300 frames` | `1` / `Result.Frames` (`Animation.FrameCount(job.Length)`) |
| Duration | `0 s` | `10.0 s` | `0` / `Result.Length` |
| Sound | — (not shown) | `sound: clip.mp4` / `no sound` / the export's own `no sound (clip.mp4: …)` | `Result.SoundPath` (the source whose sound was written), else `Result.SoundProblem`, else `no sound` |
| Encoding time | `encoded in 0.3 s` | `encoded in 3.2 s` | `Stopwatch`: copy = render + PNG encoding (clipboard write excluded); save = from the dialog closing to the file written; video = the whole export |

- Frames and duration are **always shown**, even for a still (`1 frame · 0 s`), so the format
  of the line stays constant. The sound field exists only for a video — a PNG never has one.
- No frame rate: the video is always 30 fps, frames + duration already say it.
- File size in binary units: bytes below 1 KB, whole kilobytes (`845 KB`), then one decimal
  (`12.4 MB`, `1.2 GB`).
- Duration and encoding time: one decimal, `s` suffix, `0 s` for zero; a long video stays in
  seconds (`125.0 s`). Numbers follow the Windows culture, like the export progress percentage.
- No final period, unlike the other status messages.
- Examples:
  - `Copied to the clipboard · PNG · 1920 × 1080 · 2.1 MB · 1 frame · 0 s · encoded in 0.3 s`
  - `Saved fusion-20260924-101500.mp4 · MP4 video · 1920 × 1080 · 12.4 MB · 300 frames · 10.0 s · sound: clip.mp4 · encoded in 3.2 s`
- A sound problem reported by the export (`Result.SoundProblem`, e.g.
  `no sound (clip.mp4: its sound cannot be re-encoded)`) **is** the sound field: it keeps the
  animated-content wording, reason included.

## Status Line Lifetime

- **Every** status message — the copy / save summary, paste, removal, skipped files, errors —
  stays **until the next status message** replaces it.
- `_statusTimer` and its 4 s / 8 s intervals are **removed**; errors keep their red colour.
  Export progress goes through the same `ShowStatus`.

---

## Status Line Layout

- A message wider than its column **wraps** onto further lines instead of being cut: the status
  label keeps the middle (`Percent 100`) column of the bottom `TableLayoutPanel`; its
  `MaximumSize` width is the bar's width minus the Clear button, the output buttons and the Cancel
  button when shown (`FitStatusWidth`). The bottom bar, `AutoSize`, grows in height, the preview
  above shrinks accordingly.
- It re-wraps when the window is resized, when "Force as image" appears or goes, and when Cancel
  shows or hides.

## Design Iterations

Chronological log of design refinements, of the choices the implementation run
took on its own — flagged `🧭 Implementation choices` — and of every adjustment
requested afterwards — flagged `⚙️ Post-implementation`. One entry per request,
in the order the requests were made.

### Iteration 1 — 2026-09-24

Initial design from the request and the scoping batch: the summary carries file name, format,
dimensions, file size, frame count, duration and encoding time; frames and duration are shown
for a still too; the summary persists until the next status message. Built on the MP4 export
of the animated-content workfile, implemented after it lands. Four questions remain open.

### Iteration 2 — 2026-09-24

Open questions answered: every status message now persists until the next one (the timer goes
away, not only for the summary); a video's summary names its sound source (`sound: clip.mp4` /
`no sound`); no frame rate; a message wider than the window wraps and the bottom bar grows.
The MP4 export it builds on has since been committed on `main` (`bd9e4f7`). No question remains.

### Iteration 3 — 2026-09-24 — ✅ Implemented

Go given for the code only (unit tests: no test project; README: not authorised). Work lands on
`main`, the app's standing rule. The run waits for the animated-content session to commit its
in-progress `MainForm.cs` / `GridExport.cs` edits before touching them.

### Iteration 4 — 2026-09-24 — 🧭 Implementation choices

- `GridExport.Result` gains `Frames` and `SoundPath` (the source whose sound was actually
  written), so the summary reads what the export did rather than recomputing it.
- A sound problem **is** the sound field, in the export's own wording
  (`no sound (clip.mp4: …)`), instead of a bare `no sound` plus a separate report — the previous
  message carried it in the same line anyway.
- File size: whole kilobytes, one decimal from megabytes on, gigabytes added.
- Encoding time boundaries: copy = render + PNG encoding, the clipboard write excluded; save =
  from the dialog closing to the file written; video = the whole export.
- A long video's duration stays in seconds (`125.0 s`), replacing the former `m:ss`; numbers
  follow the Windows culture; the summary has no final period.
- Wrapping: the status label's `MaximumSize` is recomputed from the bottom bar (`FitStatusWidth`);
  `ShowProgress` merged into `ShowStatus`, now identical.
- Built in a scratch worktree at `main` + `MainForm.cs`: the working tree does not compile
  meanwhile, because another session is editing `GridPreview.cs` (action-on-image), uncommitted.
- Not run by hand yet.
- No rule broken.
