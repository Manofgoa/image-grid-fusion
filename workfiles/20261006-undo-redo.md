# Undo / Redo

> Working document — Ctrl+Z undoes the last action, as many times as wanted; Ctrl+Y and
> Ctrl+Shift+Z redo it.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

A multi-level **undo history** over everything the user composes: the cells' content, the cell
effects, the grid (layout, separators) and the Global toolbar (format, global effects). Ctrl+Z steps
back, Ctrl+Y or Ctrl+Shift+Z steps forward again, a new action drops what could still be redone.

Components concerned (from the scout pass):

- `UI/GridPreview.cs` — holds the grid state: `_images` (`List<SourceImage>`, the order is the cell
  assignment), each image's `Look` (`ImageLook`, an immutable record), `_layout` (`GridLayout`,
  immutable, carrying the separators' sizes), `Format`, and the mirrors of `Soundtrack`, `Fade`,
  `Borders`. `ContentVersion` is bumped on every render-relevant change (not by `Format`).
- `UI/MainForm.cs` — holds the global effects' state (`_soundtrack`, `_soundtrackOn`,
  `_soundtrackLevel`, `_fade`, `_fadeOn`, `_borders`, `_bordersOn`), all immutable records or
  values, pushed to the preview by `ApplySoundtrack` / `ChangeFade` / `ChangeBorders`;
  `ResetGlobalEffects` and `ClearAll` are single methods; `ProcessCmdKey` (around line 827) is the
  one place every shortcut is dispatched, with a whitelist letting the explorer's search box keep
  its own keys (`_explorer.IsEditingText`, around line 830).
- `Composition/SourceImage.cs` — mutable and `IDisposable`; disposed by `GridPreview` as soon as it
  leaves the grid (removal, replacement, `Clear`).

## What the History Covers

| Area | Undoable actions |
|---|---|
| Cell content | An image added, replaced (drop, Ctrl+V, browse, explorer tile), deleted; two cells swapped; *Clear all* |
| Cell effects | Any effect setting, on / off, an effect's own *Reset*, the effects toolbar's *Reset* |
| Grid | A layout change, a separator moved, the separators reset |
| Global | The format, the Soundtrack (file, on / off, level), the Fade, the Borders — settings, on / off, their *Reset* buttons |

**Not in the history** — never a step, never changed by an undo:

- the **selection** (selected cell) and the **selected tabs** of both toolbars;
- the **playback position** of animated images (`SourceImage.Page`);
- the **app settings** (⚙ menu: base folder, Borders color, Twitter corners default, pages per
  load…), the file explorer (search, folder, favorites, tile size), the **last video**, the window.

## History Model

- A **step** is the whole composed state as it stood after an action — a **snapshot**:
  - per cell, the `SourceImage` **reference** it holds and that image's `ImageLook`;
  - the `GridLayout` (layout + separators' sizes);
  - the output format;
  - the Soundtrack (record, on / off, level), the Fade (record, on / off), the Borders (record,
    on / off).

  Every part is an immutable value or a reference: a snapshot is a handful of reference copies,
  never a copy of a bitmap.
- Two stacks: **undo** and **redo**. Committing a new step pushes the previous state onto *undo*
  and **empties *redo***.
- **Undo** (Ctrl+Z): the current state goes onto *redo*, the top of *undo* is restored.
  **Redo** (Ctrl+Y, Ctrl+Shift+Z): the reverse. With an empty stack, the key does nothing.
- The history keeps **50 steps**: a 51st drops the oldest one, and the images only it referenced
  are disposed (§ Image Lifetime).
- The history starts **empty at start-up**, the initial state being whatever the app opens with
  (the restored last screen included). It is **not persisted**.
- A **continuous gesture is one step**: from mouse down to mouse up (separator, blur and crop bars,
  pan, ✥ swap drag, any slider), and a **wheel burst** (zoom) until the wheel stops. One Ctrl+Z
  brings back the state from before the gesture.

### Step Boundaries

A universal **"the grid settled" timer** — no route has to commit its own step:

- The history keeps the **committed state** (the snapshot of the last step). Every change of the
  composed state — the preview's `ContentVersion`, the format, the global effects — (re)starts a
  **settle timer of about 300 ms**.
- When it fires **with no mouse button held**, the current state is snapshotted; if it differs from
  the committed state, the committed state goes onto *undo*, the current one becomes the committed
  state, *redo* is emptied. With a button held, the commit waits for its release.
- So a gesture, a wheel burst or a slider drag is one step by construction, and any route added
  later is covered without thinking of it. Accepted trade-off: two changes less than ~300 ms
  apart (e.g. two very quick clicks on a quarter turn) make **one** step.
- A Ctrl+Z / Ctrl+Y pressed while the timer is running **commits the pending change first**, then
  undoes or redoes: the change just made is never lost.
- A restore does not start the timer for itself: the restored state becomes the committed one.

### Restoring a Snapshot

- The preview takes the snapshot's images, looks, layout, format and global effects; `MainForm`
  takes its global effects' fields; both toolbars, their options, the checkboxes, the Copy / Save
  captions and the length readout are refreshed — the same refreshes the original actions do.
- A restore **is not itself a step**.
- **Playback** follows § Preview Playback: an undo or redo that **brings an image into a cell or
  takes one out** (the set of images differs) makes the grid **start over**; one that only
  **swaps** images, changes the layout, an effect or a global setting does **not** (a Frames
  change replays its own image only, as today).
- A Soundtrack is restored as recorded (path + duration): no file is reopened. A file gone since
  behaves as it does today when the file disappears while the Soundtrack is on.

### Image Lifetime

- An image leaving the grid is **no longer disposed at once**: it is disposed only when **no
  snapshot of either stack and not the grid** references it any more — when a step drops off the
  end of the history (depth limit) or *redo* is emptied by a new step.
- On exit, everything is disposed as today.

## Keyboard

| Key | Does |
|---|---|
| Ctrl+Z | Undo |
| Ctrl+Y | Redo |
| Ctrl+Shift+Z | Redo |

- Dispatched in `MainForm.ProcessCmdKey`, like the other shortcuts.
- A **focused text field keeps its own keys**: the explorer's search box (and any other text-editing
  control holding the focus) gets Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z for its own text undo — the
  whitelist next to `_explorer.IsEditingText` is extended.
- **Locked while exporting**, like every other change: the export keeps the state it started with.
- Ignored **while a gesture is in progress** (a mouse button held on the preview or a slider).

## Feedback and Selection

### Status Line

No button: the keys only, and a message in the **status line** after each undo / redo, naming
what changed and how many steps remain in that direction:

- `↶ Undone: image deleted — 4 more` · `↷ Redone: Blur — 1 more` · `↶ Undone: layout — nothing more`
- The action is **deduced by comparing** the two snapshots, not recorded by each route:

  | Difference | Label |
  |---|---|
  | An image appears in an empty cell / leaves a cell | `image added` / `image deleted` |
  | Another image in a cell | `image replaced` |
  | The same images in other cells | `cells swapped` |
  | One image's look | the effect's name (`Blur`, `Crop`…), `effects` when several changed |
  | The layout / only its separators | `layout` / `separators` |
  | The format | `format` |
  | One global effect | its name (`Soundtrack`, `Fade`, `Borders`) |
  | Several of the above | `several changes` |

- With an empty stack, the key does nothing and says `Nothing to undo` / `Nothing to redo`.

### Selection

- A step touching **exactly one cell** (its image or its look) **selects that cell** — or no cell
  if it ends up empty.
- Any other step (a swap, several cells, the grid, the format, a global effect) **leaves the
  selection as it is**, dropped if the selected cell ends up empty.
- The selected tabs of both toolbars never change.

## Test Impact

The repository holds **no test project** (declined since `20260923-application-v1.md`, Q&A #12,
and every workfile since): nothing is created or updated. The behaviour is checked by hand in the
launched app:

| Check | Expected |
|---|---|
| Add 3 images, Ctrl+Z three times | The cells empty one by one, in reverse order |
| Then Ctrl+Y three times | The images come back, same cells, same effects |
| Delete an image, Ctrl+Z | It comes back in its cell with its effects; the grid starts over |
| Swap two cells, Ctrl+Z | Swapped back; playback goes on |
| Drag a blur bar / a separator in one gesture, Ctrl+Z | Back to before the whole drag, in one step |
| Wheel-zoom a burst, Ctrl+Z | Back to before the burst |
| Change the layout, then the format, Ctrl+Z twice | Format back, then layout back |
| Toggle a global effect, change its setting, Ctrl+Z twice | Setting back, then off again |
| *Clear all*, Ctrl+Z | The whole grid and the global effects come back |
| Undo twice, act, Ctrl+Y | Nothing redone: the new action dropped the redo stack |
| Ctrl+Z in the explorer's search box | Undoes the typed text, not the grid |
| Ctrl+Z while exporting | Nothing happens |
| Each undo / redo | The status line names the change and the steps left; `Nothing to undo` on an empty stack |
| Undo a Blur change on one cell while another is selected | That cell gets selected |
| Undo a swap or a format change | The selection stays |
| Turn a quarter turn, Ctrl+Z at once (< 300 ms) | The turn is undone, not lost |
| Make 51 steps, Ctrl+Z 51 times | 50 undone, the 51st says `Nothing to undo` |
| Undo past a replaced image, then make enough new steps to drop it | No crash, no leak growing without bound |

## Design Iterations

Chronological log of design refinements, of the choices the implementation run
took on its own — flagged `🧭 Implementation choices` — and of every adjustment
requested afterwards — flagged `⚙️ Post-implementation`. One entry per request,
in the order the requests were made.

### Iteration 1 — 2026-10-06

Scoping batch answered (Q&A #1–4): the whole composed state is undoable, redo with Ctrl+Y and
Ctrl+Shift+Z, one step per gesture, exploration sized as straightforward (single scout pass, three
read-only agents: grid state, keyboard dispatch, global state).

Proposed design: a **snapshot history** rather than per-action commands — every part of the state
is already an immutable value or a reference (`ImageLook`, `GridLayout`, `Soundtrack`, `SoundFade`,
`GridBorders`, the format enum, the `SourceImage` references), so a step costs a few reference
copies and every route changing the grid is covered without writing an inverse for each. Images
leaving the grid stay alive while a snapshot references them. Selection, tabs, playback position
and app settings stay out of the history. Restoring follows § Preview Playback. Shortcuts in
`ProcessCmdKey`, a focused text field keeping its own undo, locked while exporting.

Left open: history depth, feedback, selection after an undo, step-boundary mechanism.

### Iteration 2 — 2026-10-06

The four open questions answered (Q&A #5–8), all on the recommended option: a history of
**50 steps**; a **status-line message** after each undo / redo naming the change, deduced by
comparing the two snapshots, and no button; the **cell the step touches** selected when it touches
exactly one; step boundaries detected by a universal **settle timer** (~300 ms, no mouse button
held), a pending change committed before an undo / redo. § History Model, § Step Boundaries and
§ Feedback and Selection updated; Test Impact gains the matching checks. No open question left.

### Iteration 3 — 2026-10-06 — ✅ Implemented

Go given (Q&A #9): code and documentation, in a dedicated worktree (`feature/undo-redo`),
fast-forwarded into `main` and removed at the end. The scope is frozen as the sections above stand.
