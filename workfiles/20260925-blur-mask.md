# Blur Mask

> Working document — a per-cell "Effects" entry point, whose first effect blurs a rectangle of the
> cell delimited by four draggable bars.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

Add an always-visible **effects toolbar** at the top of the window, reflecting the effects of the
selected image. Selecting an effect opens a second toolbar, below the first, holding that effect's
options. Clicking the selected effect again removes it.

The first effect is a **bar blur**: two horizontal and two vertical bars delimit a rectangle of
the cell, which **stays sharp**; the **outer bands** around it are blurred. Each side moves on its
own (top / right / bottom / left), so the user keeps exactly the rectangle to show. A bar dragged
close to the cell edge **snaps fully to it**, so no 1–2 px blurred strip is left along that edge
(Iteration 10).

Agreed at scoping (Q&A #1–#3):

- The effect is **per cell**: each cell carries its own effects; the rectangle lives in that cell.
- The blur options are an **intensity** and a **type** (gaussian blur or pixelate).
- The blur shows in the **on-screen preview**, in the **image export**, and on **videos during
  playback**, in real time. It is **not persisted** — the app keeps no session, and this effect
  adds none.

Relevant code (scout pass, Iteration 1):

| Concern | Where |
|---|---|
| Per-cell state | `Composition/ImageLook.cs` — immutable record (rotation, flips, grayscale, zoom, focus), carried by `SourceImage.Look`, changed through `GridPreview.SetLook` |
| Per-cell hover toolbar | `UI/GridPreview.cs` — `enum Tool` (rotate, flip, grayscale, reset), `ToolBounds` / `ToolSlot` / `ToolAt`, `PaintToolbar` / `PaintToolButton`, owner-drawn along the top of the hovered cell |

## UI — Effects Toolbar and Options Toolbar

- **No Effects button, nothing in the cell** (Q&A #5, #6): the effects toolbar lives in the main
  window's top area and is **always visible**. It reflects the effects of the **selected image**
  (`GridPreview._selected`): each effect is a toggle button, **pressed** when that effect is active
  on the selected cell. The cell's hover toolbar is unchanged.
- **Effects toolbar**: one toggle button per available effect (only *Blur* for now), on a **new
  row below the existing top bar** (threshold slider, carousel checkbox) (Q&A #18).
- **Click semantics** (Q&A #7):

  | Effect state on the selected image | Click does |
  |---|---|
  | Inactive | Activates it with its defaults and selects it (options shown) |
  | Active, not selected | Selects it (options shown) |
  | Active and selected | Deactivates it (options hidden) |

- **Options toolbar**: a row shown below the effects row while an effect is selected. For the
  blur: a type switch (*Gaussian* / *Pixelate*) and an intensity slider.
- **Effects belong to the cell + image pair** (Q&A #17): when the image of a cell changes, the
  cell's effects go back to their defaults (none active). Reset events (Q&A #19):

  | Event | Effects |
  |---|---|
  | The cell's image is replaced by another one (drop, Ctrl+V, browse) | Reset — none active |
  | An image is deleted | Reset for the images that shift into another cell |
  | Two cells are swapped | Kept — they follow the image, like rotation and zoom |
  | The layout changes | Kept — the fractions adapt to the new cell shape |

- **Selection changes** (Q&A #21): the selected effect is a property of the toolbar, not of the
  cell. When another cell is selected and the effect is active on it, it stays selected — its
  options and handles show at once for the new cell; when the effect is inactive on it, its
  button is released and the options row is hidden. With **no cell selected**, the effects
  toolbar stays visible but **disabled**; the options row and the handles are hidden. Selecting a
  cell where the effect is inactive (or no cell) **drops** the effect's selection: it is not picked
  up again on the next cell where it is active.
- **During an export** the effects toolbar is disabled and the bars hidden, like the rest of the
  locked grid.
- **Controls** (`MainForm`): the effects row is a `FlowLayoutPanel` holding a toggle `CheckBox`
  per effect, in the **standard** button look like the options' radio buttons — pressed when
  active; being selected shows through the options row below it (Iteration 12). The options row holds
  *Gaussian* / *Pixelate* radio buttons (button look) and an intensity `TrackBar` (0–100) followed
  by an `Intensity: N%` label, like the crop slider. Showing or hiding the options row changes the
  preview's height.
- **Icons** (Iteration 10): a **colored icon** left of the text of *Blur*, *Gaussian*,
  *Pixelate*, and before the intensity slider — drawn in code at the control's DPI, so **no
  dependency** is added.
- **Reset**: the cell's *Reset* tool also removes its effects, and is shown whenever an effect is
  active, even with no other action to undo (Q&A #13).

## Blur Effect — Bars and Snapping

- **Model**: the rectangle is stored as four fractions `Left < Right`, `Top < Bottom`, in `[0, 1]`
  of the **cell** (Q&A #8): zooming, panning or rotating the image does not move it. Stored with the effect's type and intensity in
  `Composition/BlurEffect.cs` (`BlurEffect`, `BlurKind`, `BlurSide`), carried by `ImageLook.Blur`
  — so exports capture it with the look, a swap moves it with the image, and *Reset*
  (`ImageLook.None`) removes it. Defaults on activation: **gaussian**, intensity at **mid-course** of the slider
  (Q&A #12).
- **Bars**: two vertical (left, right) and two horizontal (top, bottom), drawn on the **selected
  cell** only while the blur is the selected effect in the effects toolbar. Style: **full-length
  guides** crossing the whole cell, grabbable along their whole length, with a small grip at the
  middle of the rectangle's side (Q&A #16). Guides and grips are **fluorescent green**, so they
  show on any image; a hovered or dragged grip turns white (Iteration 11).
- **Drag**: each bar moves on its own axis only; the cursor is `SizeWE` / `SizeNS` over a bar. A
  bar never crosses its opposite one (a minimum gap is kept). Only the bars move: a drag inside the
  rectangle keeps the cell's current gestures (Q&A #11).
- **Snap**: while dragging, a bar within **6 px** of its cell edge lands **exactly** on it (fraction
  `0` or `1`), so no blurred strip of a pixel or two is left along that edge (Q&A #10). Logical pixels on
  screen, scaled with `LogicalToDeviceUnits`.
- **Default rectangle** on activation: **centered, half the cell's width and height** — fractions
  `0.25 … 0.75` on both axes (Q&A #9).
- **Priority over existing gestures**: a press on a bar starts a bar drag before any pan / swap
  hit-test (after the ×, the page slider, the tool buttons and the zoom slider); elsewhere, the
  cell keeps its current gestures.
- **Sizes** (logical px, scaled to the monitor's DPI): a bar is grabbed within **12 px** of it,
  the nearest one winning — wide enough on a 4K screen (Iteration 10); opposite bars keep at least
  8 px apart; grips are 32 × 8 px. Each bar snaps to **its own** edge only (left
  and top to 0, right and bottom to 1).

## Rendering

- **Hook**: `Compositor.DrawCell`, after the frame is drawn and still under the cell clip — so the
  preview, the still export, the animated export and live video frames all get the blur from one
  place.
- **Technique** (`Composition/BlurRenderer.cs`, no loop over the full-size pixels, cheap enough
  for video):
  - the cell is drawn again, without its effects, into a small offscreen bitmap covering the whole
    cell (cell size ÷ block size), then drawn back stretched, clipped to the cell **minus the
    sharp rectangle** — the outer bands (Iteration 10);
  - *Gaussian*: three 3 × 3 box-blur passes on the small bitmap, then a bicubic upscale;
  - *Pixelate*: nearest-neighbour upscale — one small pixel per block.
- **Resolution independence**: the block size goes from 1 % (intensity 0) to 10 % (intensity 1)
  of the cell's shorter side, so the preview and an export at another size look the same.
- **Order**: the blur applies to the image as shown (after rotation, flips, zoom and grayscale),
  the fitting bands included.

## Project Rules and Glossary

Requested by the user (Q&A #22): the toolbar and effect decisions of this workfile become
**general agent rules of the app**, valid for every future effect, and a **glossary** file fixes
the app's vocabulary. They live at the app root, as `RULES.md` and `GLOSSARY.md` (Q&A #23), and
are written **right away, ahead of the implementation go**, at the user's explicit request (Q&A
#24) — a user-authorized exception to the pre-implementation gate, limited to these two files.
`RULES.md` and `GLOSSARY.md` are the reference; the drafts below record what was written. A new
app-level `CLAUDE.md` imports both, so every agent session loads them (Q&A #25).

### Draft — effects rules (every effect)

- **Scope**: an effect belongs to a **cell + image** pair. Its state lives on the image's immutable
  state (next to `ImageLook`) and is not persisted.
- **Effects toolbar**: an always-visible row below the top bar, one toggle button per effect,
  **pressed** when the effect is active on the selected cell; disabled when no cell is selected.
  Nothing is added to the cell's hover toolbar.
- **Click semantics**: inactive → activates with its defaults and selects it; active, not
  selected → selects it; active and selected → deactivates it.
- **Options toolbar**: a row below the effects row, holding the selected effect's options only;
  hidden when no effect is selected.
- **Selection changes**: the selected effect stays selected when another cell is selected and the
  effect is active on it; otherwise its button is released and the options row hidden. No cell
  selected → toolbar disabled, options and handles hidden.
- **On-cell handles** of an effect (e.g. the blur bars) are drawn on the **selected cell** only,
  while that effect is selected; they take priority over the cell's other gestures only on their
  own hit area.
- **Snap**: a handle positioned relative to a cell edge snaps exactly onto it within 6 logical px.
- **Geometry** is stored in fractions of the cell, so it survives resizing and layout changes.
- **Rendering**: every effect is applied in `Compositor.DrawCell`, so the preview, the exports and
  video playback all show it; its strength is resolution-independent.
- **Reset**: the cell's *Reset* tool removes its effects too.
- **Reset events**: replacing a cell's image (drop, Ctrl+V, browse) or deleting an image resets
  the effects of the cells whose image changes; a swap or a layout change keeps them.

### Draft — glossary

| Term | Meaning |
|---|---|
| Grid (*grille*) | The whole composition, made of **cells** laid out by a **layout** |
| Cell (*cellule*) | One slot of the grid |
| Image | The content of a cell, whatever its source — still image, video, animated GIF, preview of a text / PDF or other file |
| Layout (*disposition*) | The arrangement of cells chosen in the layout strip |
| Selected cell | The cell the effects toolbar acts on |
| Effect (*effet*) | A per cell + image transformation toggled from the effects toolbar (first one: blur) |
| Effects toolbar | The top row of effect toggles |
| Options toolbar | The row below it, holding the selected effect's options |

### Iteration 9 — 2026-09-25 — 🧭 Implementation choices

No project rule was broken. Choices the frozen design left open, now in the domain sections:

- The blur is stored **inside** `ImageLook` (`Blur` property), not beside it.
- Selecting a cell where the effect is inactive, or no cell, **drops** the effect's selection.
- **During an export** the effects toolbar is disabled and the bars hidden (the design said
  nothing about exports; the grid is locked then).
- The selected effect is shown by a **2 px highlight border** on a flat toggle button; active is
  its pressed, light highlight background.
- Gaussian rendering: **three box-blur passes** on the small bitmap + bicubic upscale, instead of
  the two-step downscale the design sketched. Block size 1 %–10 % of the cell's shorter side.
- Bars: 4 px grab reach (nearest wins), 8 px minimum gap, 20 × 6 px grips, each bar snapping to its
  own edge only; bar hit-test after the ×, page slider, tools and zoom slider.
- UI labels in English, as the rest of the app: *Blur*, *Gaussian*, *Pixelate*, `Intensity: N%`.
- Showing the options row changes the preview's height (it is a docked row).

Verification: builds with 0 warnings (output redirected to the scratchpad — the running app
locks `bin/`); a scratch render check confirmed both kinds and a side snapped to the cell edge.
Not run in the app itself.

### Iteration 10 — 2026-09-25 — ⚙️ Post-implementation — Outer bands, wider bars, label, icons

Feedback after the first test in the app:

- The blur goes on the **outer bands**, not on the inner rectangle: the rectangle is what stays
  sharp. The snap keeps its purpose — no 1–2 px blurred strip along an edge.
- The bars are too hard to grab on a 4K screen: grab reach 4 → 12 logical px, grips 20 × 6 →
  32 × 8.
- The pressed *Blur* button shows "Blu": its label is clipped when the border thickens.
- Colored icons next to *Blur*, *Gaussian*, *Pixelate*, etc. A dependency is acceptable if needed
  — none is: the icons are drawn in code.

### Iteration 11 — 2026-09-25 — ⚙️ Post-implementation — Green bars

The bars in fluorescent green, so they are easy to see.

### Iteration 12 — 2026-09-25 — ⚙️ Post-implementation — Blur button clipped

The *Blur* button still showed clipped ("Bl", icon cut) once it carried an icon: the flat style's
auto-size ignores the image. It takes the standard button look of *Gaussian* / *Pixelate*, which
sizes correctly; the 2 px highlight border marking the selected effect (Iteration 9) goes — the
options row shown below the pressed button marks it.
